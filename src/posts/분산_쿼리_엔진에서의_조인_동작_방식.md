# 분산 쿼리 엔진에서의 조인 전략

분산 쿼리 엔진에서 조인(join)은 가장 기본이면서도, 성능에 결정적인 영향을 주는 연산입니다. 특히 impala, spark를 활용한 대규모 데이터 플랫폼에서는 어떻게 조인을 실행하느냐에 따라 쿼리 성능 차이가 수십 배 이상 벌어질 수도 있습니다.

# 조인의 기본 개념

조인은 두 개 이상의 테이블을 특정 키를 기존으로 묶어서 하나의 결과로 만드는 연산입니다. 대표적으로 다음과 같은 방식들이 있습니다.

- Broadcast Join: 작은 테이블을 모든 노드에 복제하여 조인
- Shuffle Hash Join: 조인 키를 기준으로 데이터를 재분배(shuffle)하고, 해시 맵을 만들어 조인
- Sort-Merge Join: 두 테이블을 조인 키 기준으로 정렬하고, 같은 키를 병합하며 조인

Spark이나 Hive 같은 엔진에서는 상황에 따라 Shuffle Hash Join 또는 Sort-Merge Join을 선택합니다.

## Impala에서 Sort-Merge Join

impala는 Sort-Merge Join을 지원하지 않습니다. 모든 조인은 Hash Join 기반으로 처리됩니다.
즉, impaladptj 실행되는 조인은 다음 두 가지 방식 중 하나입니다.

- Broadcast Hash Join: 작은 테이블을 모든 노드에 전송하여 해시맵 생성
- Partitioned Hash Join: 조인 키 기준으로 데이터를 분산시키고, 각 노드에서 해시맵 생성 후 조인 수행

## Sort-Merge Join이 없으면 어떤 문제가 생길까?

Sort-Merge Join은 조인 키 기준으로 정렬된 데이터를 한 줄씩 읽으면서 병합하기 때문에, 현재 조인 키에 해당하는 행들만 메모리에 유지하면 됩니다. 하지만 Hash Join의 경우 구조적으로 다음과 같은 한계가 있을 수 있습니다.

- 한쪽 테이블 전체를 해시맵으로 메모리에 올려야 조인이 가능하다(정렬이 안되어있다보니, 같은 키만 메모리에 올려놓을 수 없음)
- 조인 키의 카디널리티가 크거나 데이터에 skew가 존재할 경우, 해시맵이 메모리를 초과하고 디스크 스필(spill)이 발생한다.

즉, 조인 대상이 크거나 키 분포가 고르지 못하면 성능 저하 또는 장애가 발생할 수 있다.

> 스필(spill)이란 무엇인가?
> 스필(spill)은 메모리에 다 올릴 수 없는 데이터를 디스크에 임시 저장해서 처리하는 방식이다.
> 다음과 같은 상황에서 spill이 발생할 수 있다.
> * Hash Join의 해시맵이 너무 커질 때
> * 어떠한 조인 키가 너무 클 때
> * Broadcast Join 대상이 너무 클 때
> 스필이 발생하면 쿼리가 매우 느려지고, 자주 발생하면 시스템 부하도 커질 수 있기 때문에 유의해야 한다.

## Spill 문제 해결법
1. 조인 순서 바꾸기(build side 최적화)
* Hash Join은 한쪽 테이블을 먼저 메모리에 해시맵으로 올림
* 이 때, 더 작은 쪽이 build side가 되도록 조인 순서를 변경
```sql
-- 비효율적
select * from big_fact f join dim d on f.id = d.id;

-- 효율적
select * from dim d join big_fact f on d.id = f.id;
```

2. broadcast 힌트로 강제 조인 방식 지정
```sql
-- 임팔라 쿼리임
select /*+ BROADCAST(d) */
from big_fact f join dim d on f.id = d.id
```
* 작은 테이블은 모든 노드에 전송하여 로컬 조인
* 스필 거의 없음(데이터가 작다면)

3. where 필터, 파티션 프루닝으로 row 수 줄이기
```sql
select * from big_fact f join dim d on f.id = d.id where f.event_date = to_date(now())
```
* 조인 전에 필터링을 먼저 걸어서 메모리에 올라가는 row 수 감소시키기
* 파티션 컬럼 기준이면 scan이 줄어들기에 더욱 효율적

4. group by / distinct로 조인 키 줄이기
```sql
select * from (select distinct user_id from big_fact) f 
join dim d on f.user_id = d.user_id
```
* 조인 전에 중복된 조인 키를 제거하여 해시맵 줄이기
